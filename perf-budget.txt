# Perf budget checked by `make benchgate` (internal/tools/benchgate).
# One rule per line: <benchmark> <unit> <op> <limit>; medians of -count runs.
# Allocation counts are near deterministic: keep their limits tight and lower
# them when a change improves them. A rule whose benchmark is missing fails.
#
# Targets (TASKS.md, Performance):
#   BenchmarkActivityRun   allocs/op <= 80 (10 activities), B/op <= 8192
#   BenchmarkScheduler     allocs/op 0 in steady state
# Rules are added by the task that introduces each benchmark.

# internal/coro (T1.1/T1.2): hand-offs never allocate. ns/switch is a loose
# ceiling (measured ~650 on the dev box: Xeon E5-4669 v3, 6 CPUs).
BenchmarkScheduler allocs/op <= 0
BenchmarkScheduler B/op <= 8
BenchmarkScheduler ns/switch <= 2000
BenchmarkChannelPingPong allocs/op <= 0

# internal/command, internal/history (T1.3/T1.4)
BenchmarkCommitActivity allocs/op <= 0
BenchmarkHashArgs allocs/op <= 0

# internal/store/pg (T2.8): eager loop, store side, one activity per op
# (complete workflow task + complete activity with resume: 2 round trips).
# T8.2 (wire buffer instead of pgconn.Batch, context watched per context,
# reused task buffers): measured 6 allocs, ~740 B (was 52, 9.9 KiB; pgx
# path: 311, 20.4 KiB). Latency is fsync-bound (~12 ms on the dev box, 2
# commits): no rule.
BenchmarkEagerActivity allocs/op <= 8
BenchmarkEagerActivity B/op <= 1024

# internal/executor (T3.1): cold replay of a 100-activity history (302
# events): measured 38 allocs (T8.2: reused completion, calls allocated in
# blocks; was 130), ~0.9 us/event.
BenchmarkReplay allocs/op <= 42

# internal/worker (T3.5): end to end on Postgres, eager execution, one op =
# a 10-activity workflow (start, run, end; includes polling, heartbeat,
# goroutines), after a warm-up (pool connections, prepared statements).
# T8.2: median ~105 allocs/op (single runs 104-120 with polling; a loaded
# machine measured a median of 123, runs 117-148, hence the headroom; was
# ~1215),
# ~42 KiB/op, ~15 ms/activity durable. The plan's <= 80 is approached, not
# met: what remains is mostly per activity (a cancelable context, 2) and
# per execution (scheduler, state) (docs/benchmarks.md).
BenchmarkActivityRun allocs/op <= 140

# Root package (T4.1): the typed codec on the data path; a whole workflow
# through the public API (same shape as BenchmarkActivityRun, plus the
# typed layer: JSON encode/decode of inputs and outputs, activity keys).
# T8.2: median ~184 (single runs 167-200; was ~1280), headroom as above.
BenchmarkCodec/encode allocs/op <= 1
BenchmarkCodec/decode allocs/op <= 1
BenchmarkCodec/lookup allocs/op <= 0
BenchmarkPublicActivityRun allocs/op <= 240
